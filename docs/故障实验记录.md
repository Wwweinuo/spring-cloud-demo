# 故障实验记录：商品边界不可用

## 场景

假设订单创建需要查询商品信息，而商品边界暂时不可用。

## 当前三个独立服务的表现

当前 user-service、product-service、order-service 已经是独立进程，但暂未接入 OpenFeign，因此订单服务还不会主动发起商品服务远程调用。订单创建接口暂时使用请求中的商品快照字段，跨服务校验和实时价格查询留到 OpenFeign 阶段实现。

进入远程调用阶段后，订单服务不应继续生成缺少商品事实的订单，客户端应收到明确的失败响应。

## 未来拆分为微服务后的风险

商品服务不可用时，订单服务会遇到连接失败或超时。若没有超时控制，订单请求线程可能长期等待；如果盲目重试，还可能造成重复创建订单或放大下游压力。

## 后续治理方向

- OpenFeign：统一远程调用方式。
- Sentinel：超时、限流、熔断和降级。
- 幂等设计：避免重试导致重复写入。
- Trace 和统一日志：定位跨服务请求的失败位置。

本阶段只记录推演结论，不提前引入这些治理组件。
